## Core Philosophy

### Code Is Written for Humans
A program isn't just instructions for a machine but ultimately for humans: clear naming, consistent style and formatting, no duplicated logic, small composable pieces, comments that explain *why* not *what*.

### Documentation Is Knowledge
Consistent, gramatically correct, succint sentence structure for scannable information that isn't overloading, yet informative.

### Aesthetics as a core principle
Aesthetic design has real value: in code structure, in data visualization, in API design that feels natural, in documentation someone can actually navigate.

### Functional Programming Over Imperative
Composition over side effects, immutability over state mutation, declarative over imperative. Easier to reason about, harder to introduce silent bugs, more adaptable when requirements change.

### Generative AI as an amplifier
AI accelerates iteration and handles grunt work so I can focus on judgment and design. It demands the *same* rigor as code written alone - reproducibility, testing, documentation - if anything more. The hard constraint: agentic velocity must never outrun my own comprehension of the system. If I can no longer explain the architecture, that's a stop condition, not a cleanup-later item.

### Modern life-science needs to be digitalized
I firmly believe that a digitalized workflow lies at the heart of top tier, modern life-science research. Creating an data infrastructure that is safe and accessible, intermediate analysis that is automated by pipelines, end results that are beautiful and flexible, and structure that is scalable and lends itself to generative AI.

## How I Judge My Own Work

1. **Is this principled?** Would I be proud of the reasoning if someone asked me to defend it?
2. **Will others learn from it?** Is it documented well enough that someone else could pick it up?
3. **Is it beautiful?** In the aesthetic and logical sense — would I want to read or use this myself?
4. **Does it serve the human on the other end?** The colleague, the stakeholder, the future maintainer.
5. **Am I being honest?** About what I know, what I'm still learning, and what a result can and can't tell someone.
